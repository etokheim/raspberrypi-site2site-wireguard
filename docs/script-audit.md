# Separate whole-script audit

Baseline: guided site-routing feature at `717d9ac`. This follow-up is independent of the feature implementation. Reviewed the manager entrypoint, setup/apply/start, selective edits, cleanup, routing validator/hooks, DNS/verification and optional speedtest/watchdog paths. No live gateway, package manager, privileged command or network mutation was used to validate changes.

For supported ownership tags, only a complete decoded `--comment` argument equal to the ownership tag matches; the exact `"operator note --comment vpn-gateway retained"` counterexample is preserved through reapply and cleanup. ### Final ownership-escaping blocker and review evidence

libxtables serialization is not general shell serialization: the comment `vpn'gateway` appears as `"vpn\'gateway"`, which `shlex` decodes with a retained backslash. A rootless probe of the committed pre-fix helper (`34719d3`) against that listing confirmed both counterexamples: configuring `vpn'gateway` returned success without removing its rule; configuring the distinct literal backslash-apostrophe tag `vpn\'gateway` incorrectly emitted `-D INPUT 1` for the apostrophe-only owner's rule. The probe sourced the committed helper and mocked iptables; no real firewall was queried or changed.

The fix deliberately restricts ownership tags to **`^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$`** under the C locale, instead of implementing a general libxtables serializer. Only an **unset** `FW_RULE_TAG` selects `vpn-gateway`; an explicit empty value is rejected. Validation runs before installation/removal and before execution in setup/apply, saved start, selective edit (including WAN/NAT edits), and standalone cleanup. Cleanup now honors the same configured custom tag instead of hard-coding the default.

Regression evidence: `test_libxtables_apostrophe_tag_counterexamples_fail_closed` covers the exact listing and both identities; `test_unsupported_tags_refused_before_any_iptables_call` covers direct/shared removal, setup removal, installation and cleanup, including empty/non-ASCII/oversized/quoted tags and no iptables calls at all. `test_public_entrypoints_reject_tags_before_execution_phase` covers setup/apply, saved start, edit, WAN/firewall selective apply and cleanup with no network/service execution. `test_safe_custom_tag_install_and_cleanup_preserve_default_owner` proves custom-tag reapply convergence and cleanup without deleting the default owner's rule. Existing default-tag behavior and 1/64-character supported boundaries also pass. All evidence is rootless; real libxtables/kernel integration remains untested.

## Remaining risks and limits (not a clean bill of health)

- **Trusted-root input boundary:** repository code, `vpn-gateway.conf` and WireGuard peer files must be trusted and protected. Config is still intentionally sourced as Bash, and wg-quick supports executable hooks. This patch makes generated answers literal; it does not sandbox a malicious hand-edited config, repository or peer file. Do not execute from an untrusted/multi-user writable checkout.
- **Legacy empty comments:** old builds could have installed `--comment ""` rules. The new helper deliberately does not delete every empty-comment rule because ownership cannot be established. Inspect these manually before a migration, particularly a legacy WAN DROP; otherwise an old DROP can still precede a new SSH rule.
- **Unsupported historical/custom ownership tags:** apostrophes, backslashes, spaces, non-ASCII and other values outside the documented safe tag pattern are not automatically installed or removed. Setup/edit/start/cleanup fail closed before firewall mutation when such a tag is configured. Manually inspect existing rules and resolve their ownership before changing to a supported tag; merely changing the saved tag does not migrate old rules. Do not broadly delete comments based on guessed decoding.
- **Not a transactional system installer:** there is no cross-process setup lock or automatic whole-system rollback. Never run concurrent setup/edit/cleanup. Some subordinate DNS/watchdog/service helpers still use best-effort commands and can hide an internal error even though required progress-step failures now abort. Persistent firewall backend failures are reported, not automatically rolled back.
- **Cleanup needs a separate ownership/restore design:** it still has best-effort teardown, broad service drop-in removal and optional package purge/autoremove; it is not guaranteed to restore an arbitrary pre-existing host exactly. Cleanup/start are not fully detached from a disappearing controlling terminal. Use a persistent administrative session for those operations.
- **DNS/NetworkManager:** DNS setup/cleanup still contains `nmcli con up` fallback after failed `dev reapply`, which can bounce WAN. Restoring original NetworkManager DNS values and symlinked resolver state is not a complete snapshot/restore system. Route/DNS diagnostics do not prove the actual dnsmasq-bound tunnel DNS path or external site's return routes.
- **Platform/dependency assumptions:** target remains Raspberry Pi OS/Debian with Bash, systemd, iproute2 and iptables compatibility tools; Python 3 is required for guided validation and safe firewall ownership parsing (including legacy NAT setup/cleanup). On older installations without Python, install it before these operations; the helper reports the required command and refuses deletion rather than installing packages or guessing ownership. Other init systems/distributions and mixed nftables/firewalld ownership are not certified. Ookla opt-in still trusts a remotely fetched repository installer executed as root.
- **IPv4-only protection:** the new egress guard is IPv4 only and applies to Pi-bypass `all`, not legacy full-tunnel mode. No complete IPv6 site policy/leak prevention is claimed. Home-only mode intentionally retains WAN Internet and is not a private-destination kill-switch when tunnel routes disappear.
- **Real-device validation remains necessary:** no Pi reboot, cable removal, SSH hangup, actual iptables packet forwarding, NetworkManager/systemd integration, DNS reachability or live VPN was exercised. Existing administrator firewall rules inserted ahead of the owned guard, concurrent external rule writers and boot ordering need operator validation. No commits, push or PR were made by this audit worker.
